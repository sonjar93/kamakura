方針：エンジンは作り直さず、既存の関数・状態に足していく。全状態は JSON のまま（セーブ互換を保つため、新しい項目は読み込み時に補う）。

## A. 勝利条件
1. **現状**：天下統一（寺社・朝廷を除く全拠点）を5年保てばクリア、自家の拠点を全て失えば滅亡（v0.7）。観戦モードはある。
2. **不足**：勢力ごとの目標がない。平家・頼朝・奥州で目指すものが同じになっている。
3. **改善（段階1で実装）**：開始時に「目的」を選ぶ。
   - 勢力の目標（既定）：勢力ごとに条件の一覧を持ち、すべて満たすとクリア。例：平家＝1190年まで都と朝廷の主導権を保つ／頼朝＝幕府と三機関を置き、東国を押さえ、朝廷に認められる／義仲＝入京して官職を得、平家から朝廷の主導権を奪う／奥州＝1190年まで従属せず拠点を保つ。
   - 家の存続：1190年4月まで家を保つ。
   - 天下統一：これまでどおり。
   - 勝利条件なし（自由プレイ・観戦）。
   - 条件の種類は汎用（拠点の保持・朝廷の主導権・官職・幕府・東国の支配・他家の滅亡・期日）にして、シナリオの JSON に書く。
4. **影響**：checkVictory を目的別に分ける。scenario_1180.json に objectives を追加。UI は情勢タブと開始画面。
5. **テスト**：条件を満たした状態を作ってクリアになること、期日前に滅亡すれば失敗になること、セーブ・ロード後も進み具合が残ること。

## B. 朝廷
1. **現状**：天皇・上皇・法皇（幽閉の有無）・摂政・大臣の席はある。朝廷の主導権は武家ごとの dominance 数値だけ。追討宣旨・任官の申請は「自家の影響力−相手の影響力」で確率が決まる。高倉院の死・遷都・還都は史実イベント。
2. **不足**：朝廷の中に派閥がない。院宣と宣旨の区別がない。摂関の交代、皇位継承、外戚の効果がない。朝廷が自分から動かない。
3. **改善（段階1で実装）**：
   - **派閥**：院方（後白河法皇と院近臣）・摂関家（九条兼実ら）・天皇側近（高倉院・安徳天皇の周辺）・親平家の公家（近衛基通ら）・寺社と結ぶ公家。各派閥は「影響力」と「各武家への態度」を持つ。所属・態度の初期値は史実・有力説・推定を区別して記す。
   - **申請の審議**：追討・任官・院宣の可否は「派閥の影響力×その派閥の態度」の合計で決まる。武家の影響力が強くても、法皇や摂関家と不仲なら望む官職は得られない。
   - **院宣と宣旨**：宣旨は朝廷を握る側が出す。院宣は法皇が幽閉されていなければ、朝廷を握る側と対立する武家にも出せる。院宣を得ると正当性が上がる。
   - **毎月の朝廷政治（CPU）**：派閥の影響力の変動（都を押さえる武家、戦の勝敗、寄進）。法皇の幽閉解除と院政の再開。都を押さえる武家と結ぶ派閥による摂関の交代。法皇が武家と結び、対立派閥の公家を解官する。
   - **皇位継承と外戚**：天皇が都を離れたまま、または崩御したときは、院が新帝を立てる。外戚の家（安徳天皇なら平家）は朝廷の主導権に上乗せがある。
   - 理由はすべて行動ログに残す。
4. **影響**：petitionCourt・courtTick・aiCourt の確率計算を置き換える。s.court に cliques・gaiseki を追加する。古いセーブは読み込み時に補う。朝廷タブを作り直す。
5. **テスト**：派閥の態度で任官の成否が変わること。院宣は法皇の幽閉中は出ないこと。都の支配者が変わると摂関が交代しうること。天皇不在の都で新帝が立つこと。無操作で10年回して朝廷の出来事が起きること。

## C. 所領
1. **現状**：Holding に名目上の領主（proprietor・文字列）と実効支配（controller）があり、国衙には知行国主（kokuga.holder）がある。武士団は国単位。国の「影響力」は所領と兵から計算している。
2. **不足**：名目上の権利者を勢力 ID で持っていない。徴税権・軍事的支配を分けていない。国司の任命権が働いていない。
3. **改善（段階2）**：所領ごとに「本所（名目）・領家・預所／地頭（徴税）・実効支配（軍事）」を ID で持つ。年貢は徴税権を持つ者と本所で分ける。国司の任命は朝廷（B の派閥）が決め、国衙領の徴税権が動く。地頭の設置（1185年以降）で武家が徴税権に入れる。
4. **影響**：monthly・holdingsOf・provinceInfluence・所領タブ。データの移行が必要。
5. **テスト**：同じ荘園で名目上の権利者と実効支配者が違うときの収入の分配。国司を交代したときの国衙領の帰属。

## D. AI
1. **現状**：4日ごとに勢力単位で判断する（防衛の脅威→避難→攻勢の目標選定→外交・寝返り・挙兵・朝廷工作）。目標は兵力・距離・本拠かどうかで点数をつける。理由は aiLog に短く記録。
2. **不足**：敵の主力が別の戦線に出払っている隙を見ていない。兵糧と、攻めた後に守り切れるかを考えていない。緊急時も次の判断日まで待つ。ログが機械的。
3. **改善（段階1で実装）**：
   - 目標の点数に「敵陣営の兵が別の戦線に出ている割合」「自家の兵糧」「攻めたあと手薄になる自分の本拠」「落とした後に周りの敵に奪い返されないか」を加える。
   - 自家の拠点が攻められたら、その日のうちに判断する（緊急判断）。
   - 判断の理由を評定の会話テンプレ（数パターン、生成AIは使わない）で記録する。例：「源頼朝は木曽義仲の主力が西国へ出払っていると見て、北条時政らと評定し、京への進軍を決めた」。
4. **影響**：aiFaction の目標選定に点数の項を足す。aiLog に speech 欄を追加。
5. **テスト**：敵の主力が遠くにいるときの方が攻撃が起きやすいこと（同じ乱数で比較）。兵糧がなければ攻勢を見送ること。拠点が攻められた当日に防衛の判断が出ること。

## E. 情報・諜報
1. **現状**：出来事の報せは距離に応じて遅れて届く（broadcast・processIntel）。使者は道を移動する。敵軍の兵数・行き先は UI で正確に見えている。
2. **不足**：敵の兵力・行動の不確実性。密偵・内通・偽情報。
3. **改善（段階3）**：勢力ごとの「情報の確かさ」（距離・自軍や拠点の近さ・密偵）で、敵軍の兵数を幅で見せる（例：約3,000〜5,000）。密偵を送る（調査、内通の工作、偽情報で敵の進路判断を誤らせる）。AI も推定値で判断する。
4. **影響**：UI の敵軍表示（ラベル・ポップアップ・勝算）。AI の兵力参照は推定値を通す関数に置き換える。
5. **テスト**：遠い敵の推定に誤差が出ること。密偵で幅が狭まること。偽情報で AI の目標がずれること。

## F. 経済・兵站
1. **現状**：収穫は9〜10月に集中。年貢は所領の生産×3割。平家の日宋貿易・奥州の金。兵糧の購入。荒廃で減収。軍は自陣営の拠点の近くでは本拠から補給、それ以外は現地調達（荒廃・不満が増える）。兵糧が尽きると士気が下がり、逃亡が出る。
2. **不足**：輸送路の長さ・遮断、港と海上輸送、市場の価格、飢饉（養和の飢饉）、兵糧切れによる撤退・降伏。
3. **改善（段階2）**：本拠から軍までの補給線を経路でたどり、敵の拠点・軍で切れたら補給が止まる。海路は港と水軍が要る。兵糧の値段は収穫と飢饉で変わる。養和の飢饉（1181〜82年、史実）。兵糧切れが続く軍は撤退し、籠城側は降伏しうる。
4. **影響**：supplyAndFatigue・monthly・buy_food・籠城の判定。
5. **テスト**：補給線の遮断で兵糧が減り撤退すること。飢饉の年に兵糧が値上がりすること。籠城の兵糧切れで開城すること。

## G. 人物・家系
1. **現状**：家督は、決めておいた後継者→一門（父子・兄弟）→能力の順で継ぐ。後継者がいなければ滅亡。戦死・病死・捕縛がある。家臣の忠誠の値はあるが離反はない。
2. **不足**：婚姻・養子、後継者争い（嫡流と庶流）、家臣の離反と寝返り。滅亡後も一族が生き延びること（落人）。
3. **改善（段階3）**：婚姻同盟（関係の改善・外戚）、養子、家督争い（候補が複数で家中が割れると分家・離反）、忠誠が低い家臣の離反（戦の最中の寝返りを含む）、滅亡した家の一族が別の家に身を寄せる。
4. **影響**：succession・killPerson・合戦の判定・外交の提案の種類。
5. **テスト**：当主が死んで後継者が2人いるとき家が割れうること。忠誠の低い家臣が負け戦で寝返ること。

## H. 寺社
1. **現状**：延暦寺・興福寺（南都）・園城寺・熊野などは勢力として存在し、拠点・武士団（僧兵）を持つ。寄進で関係が上がる。南都焼討ちなど史実イベントがある。
2. **不足**：寺社の要求（強訴）、所領を守るための武装と行動、寄進が所領の権利に結びつくこと、建立に朝廷の承認が要ること。
3. **改善（段階4）**：寺社の CPU（所領を侵された時の強訴・武装、朝廷への要求、味方につく家の選択）。寄進は所領の本所の権利を寺社に移す形で行う（C の上に作る）。寺社の建立は朝廷の承認と工期が要る。
4. **影響**：C の所領と B の朝廷に依存する。
5. **テスト**：寺社領を押領すると強訴が起き、朝廷の態度が悪化すること。

## 歴史的正確性
1. **現状**：人物・拠点・所領・数値に確度（史実・有力説・推定・伝承・ゲーム設定・要確認）がある。官職・武家役職に成立年があり、validate() で生年・没年・役職の年代を確かめる。暦は月の大小を30日と29日の交互で近似し、閏月は1181年閏2月・1183年閏10月だけ設定している。
2. **不足**：官職の廃止・改称・任命の条件。人物の所属・親子関係・イベントの検証。暦の朔日（月の大小）の史料準拠。
3. **改善**：段階1では朝廷の派閥と所属に確度を付ける。段階4で、月の大小の表（史料の暦表に基づく）を入れて近似と分ける。任官の条件（位階の下限・前官）を設ける。validate に親子関係の年齢差・所属の年代・イベント日付の検査を足す。表示する日付は「和暦（ゲーム暦）」と明記し、史実の日付とずれうることをヘルプに書く。
4. **影響**：monthLen・validate・offices のデータ。
5. **テスト**：validate がわざと誤らせたデータ（父より年上の子、成立前の役職）を検出すること。
